# Автоматическое скрытие рекламы эфира

Актуальный режим: перед нарезкой worker берёт 12 кадров по длине исходной записи,
проверяет их локальной Qwen3-VL 4B и QR/OCR-детекторами, объединяет рекламные зоны.
Карта сохраняется в `vods.ad_protection`, кадры и промежуточные ответы — рядом с
исходником в `ad-protection`. Повторная нарезка использует готовую карту.

Ключ включает версию алгоритма, модель, размеры/время изменения файла и контрольные
суммы начала/конца. Замена исходника заставляет построить новую карту. Ограниченный
исходный фрагмент получает свою карту; его координаты не переносятся на другой файл.

Найденные области дополнительно проверяются моделью крупным планом до объединения:
ложно отмеченные чат, игровое меню и камера не включаются в карту. Эта проверка тоже
сохраняется в checkpoint и повторно не вычисляется.

На каждом клипе остаётся дополнительная QR-проверка: кратковременные коды
добавляются к маскам карты. Ключевые слова из чата не создают новые баннерные маски:
для баннеров используется проверенная моделью карта эфира. Все маски применяются **до** кадрирования и фоновых копий.
Рекламная речь и области более 30% кадра останавливают обработку. Ошибка модели,
неопределённый результат или неверные координаты не дают автоматического разрешения.
Сэмплирование не гарантирует обнаружение любой кратковременной или необычной рекламы.

После успешного рендера и записи файлов worker сохраняет `autoVerifiedAt` в доказательствах
конкретной версии. API, планировщик и публикационный worker требуют это доказательство
(или существующее ручное подтверждение старой версии). Обычные новые клипы становятся
готовыми автоматически, тестовые подборки остаются черновиками. Автопубликация по-прежнему
требует отдельно включённых настроек платформы и стримера. Проверка рекламы не проверяет
права на музыку и не включает публикацию на YouTube сама по себе.

`pnpm cf inspect-ads <vodId>` строит карту через очередь платформы.
`pnpm cf cleanup <clipId>` пересобирает старый клип из исходного эфира по карте,
сохраняя ранее выбранный режим звука. Оригинальные файлы и публикации не меняются.
Ручной редактор и обязательная галочка в интерфейсе удалены. Старый API ручных областей
оставлен для совместимости и не считается автоматической проверкой.

Для ПК нужен установленный Ollama и уже загруженная `qwen3-vl:4b-instruct`.
Worker поднимает собственный локальный сервер на временном loopback-порту; не использует
сервер Ollama других приложений. Модель работает на CPU, до восьми потоков, один кадр за раз.
Области строго внутри уже подтверждённой маски не требуют повторного крупного плана;
любое расширение за её границы проверяется отдельно.
Сервер и дочерние процессы входят в общее дерево ограничителя ресурсов ClipForge;
при нехватке ресурсов освобождаются и восстанавливаются из покадровых checkpoints.
При завершении анализа сервер и его модель выгружаются. Внешние API и автоматическое
скачивание весов не используются. `MEDIA_OLLAMA_BIN` задаёт путь к Ollama при необходимости.

# Обработка клипов и ресурсы рабочего компьютера

Локальная реализация; обновлено 30 сентября 2026. Адаптивный режим применён к локальному media worker. Действующий сайт и серверный worker не развёртывались.

## Ресурсы

Windows media worker автоматически запускается внутри Job Object. Контроллер раз в 0,5 секунды измеряет общую нагрузку, память, активность пользователя и сетевой трафик. Контроллер очереди и соединение с БД остаются работающими; приостанавливаются только дочерние процессы обработки и передачи больших файлов.

- Работа разрешена и при активности пользователя: после 15 секунд стабильного запаса ресурсов. Ожидание простоя по умолчанию отключено (`MEDIA_IDLE_SECONDS=0`).
- CPU: общий целевой уровень 90%; допустимая доля ClipForge уменьшается при росте нагрузки других процессов. Windows применяет аппаратно независимый лимит времени CPU ко всему дереву процессов. Приоритет CPU ниже обычного, диска — очень низкий.
- RAM: запас не меньше 10% физической памяти и 1,5 ГиБ. На этой машине запас около 3,2 ГиБ; допустимая память воркера меняется вместе со свободной памятью.
- При нехватке ресурсов тяжёлые процессы приостанавливаются; при длительной нехватке RAM/VRAM — выгружаются через 5 секунд. Этап повторяется после освобождения ресурсов, распознавание и скачивание используют свои контрольные точки. Управляющий процесс сохраняет очередь и продлевает срок активного задания. Сам ввод с клавиатуры или движение мыши не останавливают обработку.
- GPU: проверка раз в 5 секунд, при нехватке видеопамяти — пауза/выгрузка; при высокой загрузке — паузы между периодами работы. Это регулирование по измерениям, **не жёсткая гарантия 90% для каждого GPU-ядра/мгновения**: запущенный CUDA kernel нельзя ограничить как CPU Job Object. Чужая нагрузка тоже может превысить 90%.
- Сеть: по умолчанию до 10 Мбит/с скачивание и 5 Мбит/с отправка, то есть около 1,25 и 0,625 МБ/с. Оба лимита снижаются при занятой сети. Параллельные передачи в одном воркере делят общий бюджет. Нативный HLS скачивается последовательно; FFmpeg не используется как обход ограничения скорости.
- При ресурсной паузе передача S3/YouTube прерывает сокет и ждёт. Скачивание S3 продолжается с сохранённого смещения, YouTube — с подтверждённого сервером смещения той же resumable-сессии; повторный PUT в S3 использует тот же ключ и контрольную сумму.
- Маленькие управляющие запросы/heartbeat продолжаются. Это необходимо, чтобы не терять задания.

`MEDIA_LINK_DOWN_KBPS=20000` и `MEDIA_LINK_UP_KBPS=10000` — консервативная оценка пропускной способности интернета, **не измеренная скорость этой линии**. Она намеренно не выводится из скорости сетевого адаптера. `MEDIA_DOWNLOAD_KBPS`/`MEDIA_UPLOAD_KBPS` — верхние пределы. Настройки — в `.env.example`. Старые фиксированные 4 ГиБ / 20% больше не являются значениями по умолчанию; явный `MEDIA_MEMORY_MB` остаётся аварийным ограничителем, `0` означает адаптивный режим.

## Музыка из исходного эфира

**По умолчанию сохраняется исходный звук.** По запросу пользователя DTLN теперь можно включить для конкретного эфира или всех эфиров стримера; для Sany_Jeweler включён только эфир `v2859643784`. Обработка применяется к новым клипам. Отключение звука в паузах и фоновая музыка не используются. Старые параметры `method`/`speechSpans` в операции скрытия рекламы по-прежнему игнорируются: настройка DTLN относится к нарезке из исходного эфира.

Ниже сохранён архив исследования. Сравнение выполнено на локальных 20-секундных отрывках Sany_Jeweler и Recrent и на контролируемой смеси речи с синтезированной музыкой. По прослушиванию пользователя лучше всего сработал **DTLN + паузы речи**, но результат недостаточно хорош, чтобы рисковать звуками игры. Использованы:

| Метод | Результат и применение |
|---|---|
| Полосовой фильтр + FFmpeg denoise | Меняет тембр, музыку от речи надёжно не отделяет. Только сравнительный пример; в интерфейс как решение не включён. |
| DTLN, ONNX/CPU | Альтернативная лёгкая модель выделения речи. Некоторые слова изменяются в повторном распознавании. |
| DeepFilterNet, CPU | Лучший SI-SDR в данной контрольной смеси. Сохранены примеры для сравнения; это не доказательство лучшего звучания на любом эфире. В рабочем конвейере отключён. |
| Отключить исходный звук | Удаляет всю исходную аудиодорожку, вместе с речью и звуками игры. Резервный вариант, если отделить музыку качественно не удалось. |

В экспериментальных образцах звук обнулялся между известными интервалами речи с запасом 120 мс и плавными краями. В рабочем конвейере это отключено.

В смеси с входным SI-SDR около −0,06 дБ DTLN дал 1,71 дБ, DeepFilterNet — 4,08 дБ. Без обнуления пауз музыка в контрольных паузах снизилась всего примерно на 3 дБ. **Это подавление, а не полное удаление музыки.** Вокал песни может остаться вместе с голосом стримера. SI-SDR обычного фазового фильтра не сравнивается как оценка человеческой разборчивости. Проверка повторным ASR показала потери/замены отдельных слов; ручной экспертной оценки на слух нет.

Новые клипы проходят проверку рекламы до сборки вертикального кадра и создаются черновиками. DTLN можно включить на странице эфира или как настройку всех эфиров стримера. Отдельный эфир наследует настройку стримера либо переопределяет её на DTLN/исходный звук. Выбор применяется при следующей нарезке, без обнуления пауз речи; существующие клипы не пересоздаются. В окне клипа есть «QR-коды и реклама», автоматическое скрытие, ручные маски и подтверждение проверки изображения. При скрытии рекламы в готовом клипе его базовая аудиодорожка копируется без перекодирования. Исходники и опубликованные видео не перезаписываются. Старые экспериментальные цепочки очистки могут брать исходную версию; настройка DTLN предназначена для создания новых клипов из VOD.

Проверка обязательна для **новой отправки**: старый статус `ready` сам по себе не открывает публикацию. Ограничение проверяется в API, автоматическом планировщике и непосредственно перед загрузкой в воркере. После длительной паузы загрузчик обновляет access token и продолжает прежнюю сессию. Существующие ролики на YouTube остаются без изменений.

Ни нейросеть, ни ручное прослушивание не гарантируют отсутствие претензий Content ID. Надёжный способ сохранить голос без смешанной музыки — получить раздельный исходник: например, стример может исключить музыкальный канал из Twitch VOD через [OBS Twitch VOD Track](https://obsproject.com/kb/twitch-vod-track-guide). Из уже смешанного VOD такую отдельную дорожку получить через API нельзя. Для уже опубликованных видео есть [удаление заявленного аудио в YouTube Studio](https://support.google.com/youtube/answer/2902117?hl=en); существующие публикации автоматически не изменяются.

Исходные проекты: [DTLN](https://github.com/breizhn/DTLN), [DeepFilterNet](https://github.com/Rikorose/DeepFilterNet). Лицензии и авторство сохранены в `workers/python/licenses`.

## QR-коды и реклама

OpenCV ищет QR-коды на четырёх кадрах в секунду, RapidOCR — рекламный текст на одном кадре в секунду. Словарь содержит распространённые рекламные марки, промокоды, фрибеты и казино. Маски объединяются по всему клипу и непрозрачно закрывают найденные области **до** копирования изображения в камеру, игровой кадр и размытый фон. В готовом клипе можно вручную выделить дополнительные области. Выделение проверяется по размерам кадра.

При покрытии более 30% кадра или явных фразах рекламной интеграции фрагмент не выпускается. Для новых кандидатов выбирается другой момент; при обработке уже готового клипа возвращается понятная причина отказа.

Тестовый ролик с QR и WINLINE/PROMOCODE пропущен через реальную операцию воркера. Проверены все 30 выходных кадров на QR и два кадра на рекламный текст; центральная игровая область не закрыта. На реальном Sany-клипе детектор не нашёл QR/текстовых баннеров. Это проверка конкретных примеров, **не универсальное распознавание любой рекламы**: неизвестные логотипы, короткие вспышки, реклама без текста, спонсорские предметы и непрямая рекламная речь могут потребовать ручной маски или отказа от фрагмента.

Электроника или хип-хоп без вокала, фильтр «Attribution not required». | Доступна монетизация. Для CC BY треков обязателен указанный авторами текст в описании. Скачивать из Studio, не из чужих перезаливов. |
| [StreamBeats](https://streambeats.com/licensing/) | Бесплатный фон для игровых роликов/стримов с монетизацией; каталоги lofi, synthwave, electronic. | По текущей лицензии указание автора не обязательно. ## Установка и проверка

Используется существующий Python venv. Новые зависимости зафиксированы в обоих requirements: psutil, onnxruntime, rapidocr. Модели/бинарник ставятся явно:

```powershell
.venv/Scripts/python.exe scripts/setup-media-protection.py --kibps 256
.venv/Scripts/python.exe scripts/setup-media-protection.py --check
```

Установщик аудиомоделей оставлен для отдельных экспериментов; для скрытия рекламы DTLN/DeepFilterNet не нужны. Он последовательно получает около 31 МБ, проверяет SHA-256 и точный размер, сохраняет лицензии. При уже установленных моделях `--check` не скачивает их повторно. Whisper на управляемом desktop-воркере использует только заранее заполненный локальный кэш. Неожиданных загрузок многогигабайтных моделей во время задания нет.

Проверки: Python-тесты `test_media_resources.py`, `test_desktop_governor.py`, `test_media_protection.py`; Node-тесты ресурсов, хранилища, загрузчика YouTube и pipeline; типизация API/worker/web. Скрипты `compare-music.py`, `evaluate-music.py`, `review-media-protection.py` создают примеры без БД, публикации или обращения к S3. Артефакты — `data/reviews/media-protection/`.

Перед будущим включением новой версии действующего воркера нужно установить эти зависимости/модели и обновить его настройки: сохранённый `MEDIA_MEMORY_MB=4096` намеренно трактуется как явный аварийный предел и сам не удаляется. Этот этап не выполнен: пользователь просил сначала локальную версию.

После отключения обработки звука повторно пройдены 42 теста (34 pipeline, 6 Python, 2 запрета публикации) и полный сценарий в новой временной БД локального PostgreSQL: постановка задания через контроллер API, запрет дубликата, получение из очереди, реальное скрытие рекламы Python-воркером, сохранение новой версии, обязательная проверка перед готовностью, подготовка метаданных публикации и повторный запуск без дубликата. Исходный файл побайтово не изменился; отправок наружу — 0. Временная БД удалена после проверки. Результат — `data/reviews/media-protection/db-integration/result.json`.

Отдельно подтверждено совпадение SHA-256 закодированной и декодированной стереодорожки после закрытия QR и баннера — в том числе с переданными старыми параметрами DTLN/пауз речи. Проверен ролик без аудио. На полном Sany-клипе также проверяется неизменность исходной аудиодорожки; новый пример — `sany-ads-hidden.mp4`, отчёт — `ads-only-end-to-end.json`. Старые аудиоэксперименты не перезаписываются.

Этот сценарий выявил и помог исправить преобразование JSON-ключей драйвером БД: идентификаторы клипов с подчёркиваниями должны сохраняться буквально. Преобразование snake_case → camelCase теперь относится только к именам SQL-колонок. Проверены и исходный JSON, и чтение статуса очистки через каталог.

Повторная интеграционная проверка: `node apps/api/test/media-cleanup.isolated.mjs` после сборки API/worker. Она жёстко выбирает локальный Docker Desktop и отдельную случайную БД на порту 55432. `DATABASE_URL` из `.env` не используется: локальный API сейчас обращается к рабочей БД через SSH-туннель 55433. Создавать тестовые задания через этот API нельзя; сетевые сценарии S3/YouTube проверялись подставными ответами без реальной отправки.

Страница сравнения: `data/reviews/media-protection/index.html`; пересборка — `python scripts/build-media-review.py`. Можно открыть файл обычным браузером без сервера и дополнительных фоновых процессов.
