# Corner Assistant

Подключаемый React-пакет с Blobatar. Независим от Next, ClipForge, API и базы. Сайт передаёт разрешённую навигацию, сообщения и обработчики.

```tsx
import { Assistant } from '@clipforge/assistant';
import '@clipforge/assistant/styles.css';

<Assistant name="MyApp" identity="Анна" status="На связи" pending={0}
  mood="idle" items={[{id:'home',label:'Обзор',icon:'⌂'}]}
  messages={[]} currentItem="home"
  onSelect={id => navigateToAllowedPage(id)}
  onMessage={async text => ({text:'Ответ по данным приложения'})}
/>
```

Слева постоянная компактная навигация, справа чат. Высота фиксирована и ограничена viewport; сообщения прокручиваются внутри. Списки сущностей не входят в навигацию. Стиль следует компактной структуре Next dev tools и фиолетовой палитре Twitch. Mascot.tsx задаёт собственного персонажа ClipForge: постоянный силуэт, цвета, наушники и микрофон поверх анимации Blobatar.

`messages`: id, text, ISO time, context, facts, actions, media (видео), tone и optional technical для администратора. `onMessage` возвращает ответ с тем же содержимым. `onSelect` выполняет действие только после проверки ID сайтом. Сервер обязан проверять права независимо от интерфейса. `historyKey` включает хранение последних 60 реплик в sessionStorage; сайт обязан разделять ключи по аккаунту и области видимости и очищать при выходе.

Blobatar всегда анимирован: working — спокойное моргание с индикатором работы, success — happy, error — sad, paused — sleepy, idle — спокойное состояние. Учитывается системный reduced-motion. Escape закрывает окно. Смена сообщения не меняет высоту окна; при чтении истории новые сообщения не сбивают прокрутку.

ClipForge подключает фактические этапы очереди через /api/jobs/conversation. Сырые пути и ошибки переводятся в безопасные объяснения; diagnostics доступны только админу. Чат отвечает по данным API и показывает клипы внутри сообщений. LLM не подключена; onMessage допускает отдельный локальный/серверный адаптер. Модель не должна получать секреты или выполнять произвольные команды.

В monorepo экспортируется TSX; Next использует transpilePackages. Пакет доступен через workspace и не опубликован в npm. Для отдельной публикации нужно настроить exports на dist и включить CSS в files.

Работа над эфиром приходит карточкой со стабильным ID: этапы, счётчик готовых клипов и результат обновляются на месте. Отдельные завершения клипов не создают новых сообщений. Поле steps содержит label/state для компактной полосы этапов.
