# ClipForge

Автономная платформа Twitch: поиск каналов и игр, отбор эфиров по популярности, распознавание речи, создание вертикальных клипов, публикация и обратная связь по статистике. Для работы не нужны пользовательские аккаунты.

## Запуск

На настроенной машине: `pnpm install`, затем `pnpm start` или `run-web.bat`.
Интерфейс: http://localhost:3000. API: localhost:8420. Docker Desktop должен работать.
Запуск поднимает PostgreSQL, собирает серверные пакеты, запускает API/worker/Next и перезапускает упавшие процессы. Журналы: data/logs. Запуск при входе Windows отдельно не устанавливается.

Новая установка: Node 22+, pnpm, Docker, FFmpeg/ffprobe в PATH, Python из workers/python/requirements.txt. Скопировать .env.example в .env, заполнить Twitch credentials, выполнить `pnpm db:up`, `pnpm db:push`, `pnpm start`. Существующий .env не перезаписывать. Python по умолчанию: .venv/Scripts/python.exe.

Первый администратор создаётся при пустой таблице accounts: ADMIN_LOGIN и ADMIN_PASSWORD, либо сгенерированный пароль в серверном журнале. Регистрация закрыта. Администратор создаёт аккаунты и назначает роли. Пользователь видит свой Twitch после OAuth-подтверждения; модератор имеет чтение каталога и меняет только собственный профиль/пароль.

## Интерфейс

Вся навигация — в помощнике с Blobatar в левом нижнем углу. Разделы, стримеры, игры, события, выход; слева основные разделы, справа чат с вопросами о результатах, выборе эфира и текущей работе. Клипы доступны прямо в чате. Системные сведения о заданиях раскрываются администратором. Помощник независим от сайта: packages/assistant/README.md. Это детерминированная навигация с необязательным адаптером LLM.

## Автоматика

По умолчанию: обход каждые 10 минут, поиск каждые 30 минут, 1 новый канал за поиск, 3 эфира за скользящие сутки, 24 клипа на эфир, записи до 4 часов, резерв диска 20 ГБ. Загрузка ограничена 40 000 Кбит/с (5 МБ/с), один поток. Каждый пятый успешный прогон исследует менее обработанный канал. Повторы с задержкой, защита от дублирования и восстановление после перезапуска.

У подключённых Docker-воркеров исходники, клипы и рабочие файлы сохраняются в S3. Локальная копия удаляется только после подтверждения загрузки; для следующего задания нужные файлы восстанавливаются с проверкой SHA-256. Накопленный кэш переносится отдельными заданиями `heavy.archive-vod`. Метаданные и расшифровки остаются в PostgreSQL.

Речь: локальный Whisper large-v3. Отбор: сигналы звука/речи, разнообразие моментов и ограниченная обратная связь по публичной статистике. Приватные просмотры не влияют на приоритеты.

## Проверки и внешние подключения

Управление из инструментов и командной строки: `pnpm cf --help`.
[Клиент платформы и API публикаций](docs/platform-tools.md) используют ту же авторизацию,
очередь и историю, что и сайт. Для обычных операций не нужны отдельные скрипты,
SSH или изменения данных напрямую в БД.

`pnpm typecheck`, `pnpm build`, `pnpm test`, `pnpm test:integration`, `pnpm check:integrations`.
HTTP-тестам нужны работающие API и БД. Реальный тест обработки: задать TEST_SOURCE_VIDEO и выполнить `node apps/worker/test/pipeline.integration.mjs`.

YouTube: AUTO_PUBLISH_ENABLED=false, YOUTUBE_PRIVACY=private по умолчанию. Фактическая видимость и метрики проверяются каждый час. Текущий OAuth требует повторного подключения владельцем. Проверенные результаты и ограничения YouTube/TikTok/Instagram: docs/platform-status.md.

## Структура

- apps/web, apps/api, apps/worker — основная платформа.
- packages — db, contracts, jobs, Twitch, YouTube, pipeline, assistant.
- workers/python — вычислительные задачи Whisper/OpenCV/NumPy.
- legacy — старое Python-приложение и документация, не участвуют в запуске.

Данные и клипы: data/out; модель: models; оформление: assets. Перенос старого интерфейса в legacy не удаляет материалы.
